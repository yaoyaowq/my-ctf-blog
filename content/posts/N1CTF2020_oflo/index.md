![1790077079570](1790077079570.png)

main函数的主要流程:

首先调用sub_4008B9;接着接收输入的19个字符;随后调用mprotect，修改sub_400B54 & 0xFFFFC000为首页地址区域的权限，将其改为 r | w | x ;紧跟着是改变400A69处的前10个字节;最终是调用sub_400A69检查flag是否正确。

```
程序开始
   ↓
调用 sub_4008B9
   ↓
接收用户输入 19 个字符
   ↓
调用 mprotect
   ↓
将代码所在内存页权限修改为
R | W | X
   ↓
使用输入的前 5 个字符
循环 XOR 修改 sub_400A69
的前 10 个字节
   ↓
恢复出运行时真正执行的代码
   ↓
调用 sub_400A69
   ↓
进行 Flag 校验
   ↓
┌───────────────┐
│   校验是否正确 │
└───────┬───────┘
        ↓
   正确        错误
    ↓            ↓
输出 Cong!     返回失败
```

由于题目是:N1CTF2020 - oflo,所以输入的前5个字符是n1ctf，

使用IDA中的python，修改400A69。

```
import idc

s = 'n1ctf'

for i in range(0x400A69, 0x400A69 + 10):
    c = idc.get_db_byte(i)
    c ^= ord(s[(i - 0x400A69) % 5])
    idc.patch_byte(i, c)
```

改完发现400A69还是不能进行反汇编，


那么

```

```

就是没用的指令，直接nop

这里出现buf。由于内部太复制，直接动态调试，查看buf的值。



我在400CE7处下断点，查看rdi的内容。![1790080533775](1790080533775.png)

![1790080570937](1790080570937.png)

这里说明了sub_A69函数调用的位置和buf作为第一个参数传入函数。在LINUX中第一个参数由rdi保存。

![1790080470356](1790080470356.png)在这里能看到buf的前14个字符是 "Linux version  "

 因此我们很容易便能得到 flag 内容 

```
s = "5-\x11\x1AI}\x11\x14+;>=<_"
b = "Linux version "
ans = ""

for i in range(14):
    ans += chr(ord(s[i]) ^ (ord(b[i]) + 2))
print(ans)
```

![1790080887242](1790080887242.png)

结果是 {Fam3_is_NULL} 

加上前面的5个字符，完整的flag就是n1ctf{Fam3_is_NULL}。
